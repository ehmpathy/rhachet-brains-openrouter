### D1 — `genTempDir()` lacks its now-required `slug` — ✅ fixed

- **what**: `tsc` → `TS2554: Expected 1 arguments, but got 0` at `src/domain.operations/supply/genZdrRefreshClaim.integration.test.ts:12`
- **how**: `git diff origin/main` on the test file is empty. the upgrade moved `test-fns` 1.10.0 → 1.17.0
- **why**: test-fns 1.17 declares `genTempDir(input: { slug: string; ... })`. the slug names the test that made the dir, so a debugger can trace a stale dir to its author
- **fix**: `genTempDir({ slug: 'genZdrRefreshClaim' })`. no other zero-arg call in `src/`. `test:types` passes

### D2 — `"private": true` would flip the public repo private and block `npm publish` — ✅ fixed

- **what**: hazard H1. not caught by a test; repaired here as a safe, clean one-line fix
- **how**: `provision-github.bad-practice.implicit-package-privacy` backfilled `"private": true`; `resources.ts` now maps any non-`false` to a private repo
- **why**: the practice fails closed. it cannot know this package publishes to npm. its readme names the fix: a public, published package declares `"private": false` by hand
- **fix**: `package.json` → `"private": false`. the practice detector accepts any boolean, so a re-run keeps it
