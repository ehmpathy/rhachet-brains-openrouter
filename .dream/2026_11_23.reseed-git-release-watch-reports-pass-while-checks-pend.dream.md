# 🌙 dream: git.release --watch reports "all checks passed" while checks still run

kind: reseed · owner: ehmpathy/rhachet-roles-ehmpathy (mechanic, skill git.release) · caught 2026-11-23

## .the cue that fired

after the first push of pr #37 (ehmpathy/rhachet-brains-openrouter), `rhx git.release --watch` printed "all checks passed". `gh pr checks 37` showed integration + acceptance shards still unresolved; both later failed.

## .the gap, precisely

the watch read a check set before the dynamic shard jobs (`test-shards-*`, spawned by `enshard`) had registered, saw every registered check green, and declared success. a pass verdict over an incomplete set is a failhide.

## .the shape of the fix

- treat the set as complete only once the workflow run itself reports `completed`, not once each listed check does
- or require the union jobs (`test-integration`, `test-acceptance-locally`) to be present before a verdict
- clamp: a fixture run where shard jobs register after the first poll; the watch must stay unresolved

## .why it is not done in this round

the skill lives in another repo; this route may not edit it.
