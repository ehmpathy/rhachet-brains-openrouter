# 🌙 dream: show a hop while the caller waits on it

kind: observability · owner: rhachet-brains-openrouter · caught 2026-10-21

## .the cue that fired
5.3 self review `has-critical-paths-frictionless`, rubric line "visible status throughout"
(`def.frictionless`). the hop path serves, but a throttled host costs the openai client's two
retries — up to 60s of `retry-after` each — before the hop, and `brain.ask` says naught until it
returns. a marked fault with no host name costs about two minutes (readme § host faults).

## .the gap, precisely
- the supply path holds no log channel: no `context.log` in `src/domain.operations/supply/*.ts`
  (`rhx grepsafe --pattern "context\.log|log: LogMethods" --path src/domain.operations/supply`)
- the status is visible only after the fact, in `supply.attempts` (readme: "the hops are silent on
  success. log `supply.attempts` to see why an ask ran slow")
- the floor walk had the same silent wait before this PR; the admitted-set hop adds a second path
  with it

## .the shape of the fix
1. accept an optional `log` (`LogMethods`) in the `brain.supplier.openrouter` context, thread it
   into `getOneSuppliedCompletion`'s context
2. on each host fault that leads to a hop or a walk step, `log.info('openrouter host fault, hop',
   { tag, outcome, retryAfter })`
3. clamp: a fake `log` collects calls; a 429-then-serve asserts one info line per hop, none on a
   first-try serve

## .why it is not done in this round
not CLEAN: a new context dependency on `brain.ask` ripples into the public contract, the readme,
and every caller's context shape — outside a p0 cut to "the host-400 step and the 429 hop only".
the wait itself is F9 (kept by robot:director); the retry cut is
`v2026_10_21.measure.retry-cut-on-hop-sends`. this dream covers only the status shown while it waits.
recorded as fulcrum F12.
