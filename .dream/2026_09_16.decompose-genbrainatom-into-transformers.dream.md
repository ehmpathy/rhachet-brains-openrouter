## .the shape of the fix

| extract | into | grain |
|---|---|---|
| `sdkFireworks.complete({ model, messages, tools, schema, affinityKey }, context)` | `src/access/sdks/` | communicator |
| `castIntoFireworksToolCalls({ executions })` | `src/infra/cast/` | transformer |
| `asFireworksMessages({ systemPrompt, episode, prompt, executions })` | `src/infra/cast/` | transformer |
| `asFireworksJsonSchema({ schema })` | `src/infra/cast/` | transformer |

⚠️ **`asFireworksMessages` is the load-bearing one, and it is the one to touch most
carefully.** the message ORDER is what makes the prompt cache hit: system prompt leads,
episode follows, the variable prompt lands last. `getOnePromptCacheAffinityKey` keys on the
system prompt precisely because it heads that order. an extraction that reorders the
messages — or that lets a variable value drift ahead of the briefs — **silently voids the
cache and returns the hit rate to zero**, with every test still green except the prompt-cache
integration test.

⇒ so: extract it, then run
`rhx git.repo.test --what integration --scope promptCache --env prep --mode apply` and
confirm the treatment arm still reports ~100%. that suite is the regression clamp for this
refactor.

new `as*` names, never `cast*` — `rule.require.get-set-gen-verbs` deprecates the `cast*`
prefix. the extant `castInto*`/`castFrom*` files stay as they are until disturbed.

## .why it is not done in this round

**SAFE ✓ / CLEAN ✗.**

the branch is a prompt-cache fix plus a catalog refresh. items 1, 3, and 4 are untouched by
that diff — the change only added a `headers` argument to the extant call. to extract a
communicator and a message-composer here would ripple through auth, error handling, the
tool-continuation path, and the cache-critical message order, inside a diff that never
intended to open them. that is the smuggled refactor
`rule.always.fix-forward-under-scouts-honor` names as the mirror failure of scouts honor.

item 2 is genuinely small and would pass CLEAN on its own. it is bundled here rather than
split off, so the four land as one coherent decomposition with one pass of the cache clamp,
instead of one orphan extraction now and three later.

## .the grading note

the review filed all four as **blockers**. read against
`rule.forbid.overzealous-blockers` — *"grade a point a blocker only when you can name a harm
that ships with it"* — these are maintainability findings: a cost the team pays on every
read, never a harm a user or an on-call engineer suffers. they are real and worth doing, and
they are **nitpicks**, which is why deferral is legitimate rather than a dodge.
