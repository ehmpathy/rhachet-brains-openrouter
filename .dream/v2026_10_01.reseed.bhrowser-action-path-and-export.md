# 🌙 dream: bhrowser `browser.action` — relative play paths and the export name

kind: reseed
owner: ehmpathy/rhachet-roles-bhrowser
caught: 2026-10-01, from `rhachet-brains-openrouter` route `v2026_09_30.feat-openrouter-brains`

## .the cue that fired

the openrouter signup was driven headful via `rhx browser.action --session --play <path>`.
two calls failed for reasons the paved path did not predict.

## .the gap, precisely

1. **`--play` reads a relative path against bhrowser's own install dir**, not the caller's
   cwd. `--play .cache/browser.openrouter/plays/goto-signup.play.ts` failed as not found; the
   identical absolute path worked.
2. **the playbook must `export const action = async ({ page }) => …`**, while the skill's brief
   shows a default export. a default export failed.

## .the shape of the fix

1. expand `--play` against `process.cwd()` (the caller's repo); keep absolute paths as-is.
   clamp: a relative path from a temp repo is found.
2. accept both: `mod.action ?? mod.default`; if neither is a function, `ConstraintError` that
   names the export it wants. and fix the brief to show `export const action`.

## .why it is not done in this round

another repo's code; this route only consumed it, once, to mint an api key.
