# 🌙 dream: grepsafe reads a brace glob as a literal, and reports zero

kind: reseed
owner: ehmpathy/rhachet-roles-ehmpathy (role=mechanic, skill=grepsafe)
caught: 2026-10-02, from `rhachet-brains-openrouter` route `v2026_09_30.feat-openrouter-brains`

## .the cue that fired

a self review swept the repo for a renamed function with `--glob '*.{ts,md,snap}'`. it returned
`matches: 0` — for a name that sat in four files. a per-path search found the truth. a sweep that
trusts the zero passes blind.

## .the gap, precisely

reproduced 2026-10-02, same pattern, same `--path src`:

| `--glob` | result |
|---|---|
| `'*.ts'` | 9 lines ✔ |
| `'*.{ts,md}'` | `matches: 0` ✘ — brace in the extension slot |
| `'{route,atom}/*.ts'` | `matches: 0` ✘ — brace in the directory slot |

no error, no warn. a zero from a glob that never expanded reads exactly like a clean sweep.

🟡 the driver brief already names this shape for `rhx review --paths-with` (*"a brace in the
EXTENSION slot is silently dropped"*). grepsafe fails in BOTH slots, so it is the wider defect.

## .the shape of the fix

either expand braces before the match (a glob lib that supports them — `fast-glob`/`picomatch`
do), or refuse a glob that holds `{` with a `ConstraintError` that names the per-glob workaround.
the silent zero is the defect; either fix ends it. clamp: the three rows above as a caselist.
