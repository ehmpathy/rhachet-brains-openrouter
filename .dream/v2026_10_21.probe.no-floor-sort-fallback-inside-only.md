# 🌙 dream: probe whether a fallback stays inside `only`, so a no-floor sort can survive a throttled top host

- kind: probe
- owner: rhachet-brains-openrouter
- caught 2026-10-21, on `beav/feat-thought-cap-and-host-sort`
- ✅ resolved 2026-10-21, same branch, at stone 5.3: openrouter's docs state `only` bounds every
  fallback, so a sorted admitted set sends `allow_fallbacks: true` (F31 re-taken). step 3's socket
  clamp does not fit: the fallback runs inside openrouter, not this package. the clamps are the
  unit body test (`asProviderPreference.test`) and the live [case2e] and [case7] runs

## .the cue that fired

acceptance [case2e] (`openrouter/deepseek/flash/privacy=full&sort=throughput`) drew
`429 Provider returned error` three runs in a row, then served. integration [case7], on the same
slug, passed in the same minutes.

## .the gap, precisely

every call sends `provider: { only: [...], allow_fallbacks: false }`. with a `sort`, openrouter
aims at the top host of the admitted set. while that host stays throttled, every no-floor ask
fails, and both live tests on the route can flake.

## .the shape of the fix

1. probe live: send `only: [a, b]` with `allow_fallbacks: true` and `sort: 'throughput'`, where
   `a` is throttled or refused. check that the served `provider` is always in `only`.
2. if a fallback stays inside `only`, send `allow_fallbacks: true` on the admitted-set path. the
   admit check (`response.provider ∈ only`) already refuses any host outside the set, so the
   enforced promise holds either way.
3. clamp it: a socket test where the first admitted host answers 429 and the next serves.

## .why it is not done in this round

it changes a key that every 0.1.3 call sends, on a premise (fallbacks inside `only`) no probe has
checked. that makes it unsafe to ride along. F31 holds the call for the wisher.
