kind: refactor · owner: rhachet-brains-openrouter · caught 2026-10-21

## .the cue that fired
5.1 peer `enroll-impl-arch-defects`, i006 points 2, 4, 5: two peer walks share one decision
(`asHostFault`) but not the code around it.

## .the gap, precisely
- `getOneAdmittedSetCompletion` imports `getOneFloorCompletion` as a fallback, and takes
  `expectsJson` + `setJsonIgnoredTag` only to hand them on. so a prose reply after a marked
  unnamed fault writes a 7-day json-ignored tag; the same reply on a fault-free no-floor ask
  writes none and throws at `getOneReplyDefectError`
- the fault step (classify, drop the cache on `refused`, append the trail, keep `retryAfter` and
  `faultLast`) sits in two catches; the cache rule already drifted once (fixed in i006)
- `getOneCompletionFromEndpoint` and `getOneCompletionFromEndpoints` both wire
  `asProviderPreference` + `chat.completions.create`; a field added to one misses the other
- `getOneFloorExhaustedError` re-runs `asHostFault` on `faultLast` to learn its outcome
- the set-wide send of a walk leaves no row in `attempts`
- no test drives a json ask into the walk fallback: the admitted suite's fake
  `setJsonIgnoredTag` throws, so a prose reply after a marked unnamed fault is unpinned
  (5.1 r10 i008 point 5)
- a known asymmetry on openrouter's own account 429 (unmarked): the admitted set rethrows it in
  one send (c9), but the floor walk, where the mark is inert (I3), walks every host at about 3
  sends each and refuses with every host `throttled`. c9's reason — a walk prolongs the limit and
  blames the hosts — holds for the floor walk too (5.1 r10 i008 point 6)

## .the shape of the fix
- one walk whose step admits a group of endpoints: floor starts with groups of one; no floor
  starts with the whole qualified set and narrows to groups of one after a marked unnamed fault
- one `catch` owns the fault step; one send communicator (the singular delegates to the plural)
- carry `faultLast: { error, outcome }` so the refusal reads the decision, not the raw error
- one rule for the unmarked fault on both paths: rethrow in one send, as c9 does
- a clamp: `expectsJson: true`, a marked unnamed 429, then a prose reply — assert
  `setJsonIgnoredTag` is called and the trail holds `prose`
- land beside the `Floor*` rename (`.dream/v2026_10_21.rename.floor-attempt-to-supply-attempt.md`)
  and #22/#23's reply-shape hop — that third fault path is the third use F11 waits for

## .why it is not done in this round
not CLEAN: it reshapes both walks and the public report type, past the p0 wish's one-seam scope.
the behavior today is pinned by unit, real-client, and live tests, which the refactor can keep.
