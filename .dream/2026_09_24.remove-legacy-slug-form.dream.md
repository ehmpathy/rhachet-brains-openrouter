# 🌙 dream: collapse the legacy slug form into retired, or drop it

kind: refactor
owner: unclaimed
caught: 2026-09-24

## .the cue that fired

the wisher asked *"whats legacy vs retired?"* — the two words sit side by side in
`src/domain.operations/atom/slug/` and do not tell themselves apart at a glance. the answer
took a table to give:

| | legacy | retired |
|---|---|---|
| who caused it | **us** — we changed the slug shape | **fireworks** — they retire the model |
| what changed | the **name** | the **model** |
| the model behind it | identical, always | on its way out |

🔴 **a distinction that needs a table is a defect in the name, never a chance to teach.** the
first instinct once it was explained was *"no legacy, only retired; hardcut"* — the right
reflex and the wrong remedy, since the two are genuinely different facts.

## .the gap, precisely

`legacy` carries a real ambiguity. it says *"old"*, which is true of a retired model too, so
the word does not name the axis that actually separates them: **who moved, and what moved.**

checkable evidence, 2026-09-24:

- `AtomSlug.legacy.ts` holds 12 rows, each a pure rename — its own header says so:
  *".note = a pure RENAME — every row names the identical model it always did."*
- `AtomSlug.retired.ts` holds 5 rows, each a model fireworks announced a retirement for, 3 of
  which have no single successor
- `asPinnedAtomSlug.ts` reads them in two distinct steps for exactly that reason —
  `asCanonicalAtomSlug` (what did you mean) then `walkOneRetirementRoute` (does it serve)
- a slug can be BOTH: `fireworks/deepseek/v4-flash` → `flash/v4` → `flash/v4.1`, two hops

⇒ so the concepts must stay two. it is the **word** that is wrong.

## .the shape of the fix

pick one of two, in order of preference:

**A. rename `legacy` → `renamed`** (the cheap, honest fix)

```
AtomSlug.legacy.ts            ->  AtomSlug.renamed.ts
FireworksBrainAtomSlugLegacy  ->  FireworksBrainAtomSlugRenamed
PINNED_BY_LEGACY_SLUG         ->  PINNED_BY_RENAMED_SLUG
isLegacyAtomSlug              ->  isRenamedAtomSlug
```

`renamed` names the act and its actor — WE renamed it — so it cannot be read as *"fireworks
is done with this"*. it also pairs symmetrically with `retired`
(`rule.prefer.symmetric-term-pairs`). mechanical: one `sedreplace` per symbol, plus the
`AtomSlug.ts` and sdk export doc lines.

**B. drop the form entirely** (only once it is provably safe)

the hardcut, which is what the first instinct reached for. it needs proof that **no consumer
names an old slug**, and the evidence today says at least one does:
`rhachet-brains-bhrain` calls `genAtomFireworks({ slug: 'fireworks/deepseek/v4-flash' })` at
`invokeBrainArch1.fireworksai.deepseek-v4-flash.codewrite.integration.test.ts:192`, and
recommends it at `readme.md:203`.

⇒ so B is gated on a cross-repo sweep, then a major version. A is available now.

🟡 whichever is taken, the **clamp survives**: `asPinnedAtomSlug.test.ts` case6 holds that
every old name reaches a live model and that the set covers every pinned slug. that test was
dogfooded red on 2026-09-24 and must stay red-able after the rename.

## .why it is not done in this round

the wisher said *"but keep it for now"* — an explicit deferral, and the correct call: this
round's promise is that a consumer feels no churn, and a rename of the very map that keeps
that promise is the one edit most likely to break it under a deadline.

⚠️ it is also not purely CLEAN even as option A: `FireworksBrainAtomSlugLegacy` and
`PINNED_BY_LEGACY_SLUG` are **exported from the sdk** (`src/contract/sdk/index.ts:58-60`), so
a rename is a published-contract change rather than an internal one. that ripples past the
diff this round opened.

⇒ fulcrum: the word `legacy` was taken as the name for the pre-tier form at ~70% confidence,
and is now known to read ambiguously against `retired`. rework is DIRTY only because the
symbol is exported; the code itself would be a clean sweep.
