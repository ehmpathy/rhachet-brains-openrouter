# 🌙 dream: with-simple-cache supports stale-while-revalidate

kind: reseed

caught: 2026-10-02, from `rhachet-brains-openrouter` route `v2026_09_30.feat-openrouter-brains`
dispatched: ehmpathy/with-simple-cache#68, 2026-10-02, at the wisher's ask

## .the ask

add a stale-while-revalidate option to `withSimpleCacheAsync`, so a value past its fresh window
is served at once while one refresh runs behind it.

```ts
withSimpleCacheAsync(logic, {
  cache,
  expiration: { minutes: 60 },          // fresh: serve, no refresh
  staleWhileRevalidate: { hours: 24 },  // stale: serve now, refresh behind (name open)
});
// past fresh + stale, or absent: wait for the logic, as today
```

## .the semantics we need

- **fresh** (age < expiration): serve, as today
- **stale** (expiration <= age < expiration + swr): serve the cached value at once; start ONE
  refresh per key per process (dedupe as the in-flight promise cache does today); write it back
  on success
- **expired** (past both, or absent): wait for the logic, as today
- **a failed background refresh** never rejects the caller (they already hold a value). it is
  surfaced — an `onRefreshError` hook, or a log — never silently swallowed, and the stale value
  stays in place so the next call retries
- the age must come from the write time, so the disk entry needs a written-at stamp beside its
  expiry

## .why

openrouter's zero-data-retention list is a ~1.17MB read that covers every model, with no
per-model form (probed 2026-10-02: every query variant 404s or is ignored). a fresh read costs
~140–250ms in front of an llm ask. a stale index is safe there — openrouter also enforces zdr on
its side, so a stale yes costs one walk hop at worst — so the read belongs behind the ask, not in
front of it.

## .the shape today

hand-rolled beside `simple-on-disk-cache` in `rhachet-brains-openrouter`:
`src/domain.operations/route/sdkOpenRouterEndpoints.ts`, `getAllZdrTagsByModel` (an entry
`{ at, index }`, a 24h disk expiry, a per-process in-flight map). with this option it collapses
back to one `withSimpleCacheAsync` call, like the endpoints read beside it.

## .clamps owed

- a stale hit returns the cached value with no wait on the logic
- a stale hit triggers exactly one refresh, even under N concurrent callers
- a refresh failure does not reject the caller, is surfaced, and leaves the stale value
- past expiration + swr, the caller waits for the logic

## .why it is not done in this round

another repo's contract. our half ships now, hand-rolled; it swaps to the option once released.
