# vision — thought cap + host sort

## .the contract, in one sketch

```ts
// bhrain's path: the choice atom already holds its creds, bound by rhachet
const result = await context.brain.brain.choice.ask({
  role: {},
  prompt,
  schema: { output },
  effort: { budget: { tokens: 6000 } }, // or 'low' ≡ { level: 'low' }; omit for 0.1.3
});

result.metrics.size.tokens.thought; // 4100 — null where the host reports none
result.supply.choice.sort;          // 'throughput', when the slug says so
```

```
openrouter/deepseek/flash/floor&speed=min50tps&privacy=full&sort=throughput
                                                            └─ the host sort: a slug word
```

| caller writes | request body gets |
|---|---|
| `effort: { budget: { tokens: N } }` | `reasoning: { max_tokens: N }`; `reasoning` joins the params a host must list |
| `effort: 'E'` or `{ level: 'E' }` | `reasoning: { effort: E }`; same param requirement |
| `sort=S` in the slug, no `floor` word | `provider.sort: S` beside `only`; fallbacks on, bounded by `only`, so a throttled top host steps aside (F31) |
| `sort=S` in the slug, with `floor` | `provider.sort: S` too; and the walk tries qualified hosts in S order, one per hop. with one host per hop, the forward alone would do naught (F03) |
| naught | the 0.1.3 body, byte for byte |

two levers, two channels, each where its owner chooses:

- **thought is per ask.** it rides rhachet's generic `effort` on the ask input, beside `plugs`.
  the shape is rhachet#595's, verbatim: `effort?: BrainEffortLevel | PickOne<{ level; budget: { tokens } }>`,
  with the level a generic passthrough that each brain validates against its own
  `spec.supports.effort`
- **sort is per atom.** it is a host choice, like `floor`, `speed`, and `privacy`, so it is one
  more word in the slug's filter segment. a slug names the supply; a listed slug is how a
  `choice` picks one (`AtomSlug.filtered.ts`)

## .the walk survives a cut or stalled host

a long ask with no thought cap looks, from outside, like a host that never answers. measured on
this route, 2026-10-21: four of six peer reviews of this vision ran on
`openrouter/deepseek/flash` via this repo's dist and returned no verdict. one body ended mid-json
(`SyntaxError: Unexpected end of JSON input`, raised at `getOneFloorCompletion.js:66`). three
hung until the 21-minute review clock. the same ids answered live in 12s
(`BrainAtom.config.integration`), so openrouter served; single hosts did not.

the floor walk already steps past a host that failed (`isReplyFailed`, `asStepOutcome`). two
failures slip past it:

| host does | today | after |
|---|---|---|
| ends its body mid-json | a raw `SyntaxError` escapes the ask | a host failure: step to the next qualified host, and the supply report names `body-cut` |
| stalls past the per-hop bound | the ask hangs as long as the caller's clock allows | the hop aborts at the bound, body included; step to the next host, report names `stalled` |

- the sdk `timeout` stops at the headers, so a host that stalls its body hangs past it
  (`sdkOpenRouterEndpoints.integration.test.ts:188-192`). the bound is an abort race over the
  whole call, as that test already does
- the bound is per hop and generous (F11). it bounds a dead host, never a slow answer: the
  thought cap is the lever for a slow answer
- on a slug with no `floor` word there is no next hop in our hands, so the same two failures
  raise a named `MalfunctionError` with the host and the bound, never a raw `SyntaxError` or a hang

## .rhachet#595 — patched here, upstream in flight

rhachet 1.48.1 has no `effort` on the ask and no `tokens.thought` in its metrics. #595 adds both.
until it releases:

- this repo carries `patches/rhachet@1.48.1.patch` (pnpm `patchedDependencies`). it adds exactly
  #595's types: `effort` on the atom ask and the choice ask, `spec.supports.effort`, and
  `metrics.size.tokens.thought`. no runtime code: rhachet already passes the ask input through
  untouched (`asBrainAtomWithContextBound.js:20`)
- this package normalizes the string alias itself (`'low'` → `{ level: 'low' }`). once rhachet
  normalizes too, ours is a no-op on an object
- rhachet is a **peer** dependency, so the patch never ships. bhrain carries the same patch, or
  waits for the release
- once #595 releases, bump rhachet and delete the patch. a shape change in review costs one
  mapping site here (F10)

## .the outcome world

**before.** a bhrain review ask thinks until the host's output limit. it writes no verdict and
returns `finish_reason: length` with empty content. bhrain reads *"cut off… ask for a shorter
reply"*: the wrong fix. it paid ~2× the input cost for naught. 0.1.3 offers no lever to cap the
thought, and none to prefer a fast host over a cheap one.

**after.** `stepReview` asks with `effort: { budget: { tokens: N } }`, sized to leave room for
the verdict and to fit its deadline. the host thinks up to N, then answers. each reply reports
`metrics.size.tokens.thought`, so bhrain sizes N from a week of data, not a guess. a reply that
is still all thought fails loud: the error says the whole reply was thought, and names the budget
to lower. a lane under deadline picks the `…&sort=throughput` slug and gets the fastest qualified
host first. every privacy and speed promise still holds.

**the aha.** an empty verdict was never a short reply. it was a reply that never started. once
the error says so, and the thought tokens sit beside it, the fix is one number.

## .mental model

- **to a friend:** "tell it how hard it may think before it must answer, and pick the fast host
  or the cheap one."
- **analogy:** an exam with a scratch-paper limit. past the limit, you must write the answer. the
  new error is the proctor who says *"you filled the scratch paper and left the answer blank"*.
  the old one said *"your answer was too long"*.
- **their words vs ours:**

| caller says | openrouter says | rhachet + this package say |
|---|---|---|
| think budget, reasoning limit | `reasoning.max_tokens` | `effort.budget.tokens` |
| reasoning effort | `reasoning.effort` | `effort.level` |
| reasoning tokens | `reasoning_tokens` | `metrics.size.tokens.thought` |
| fast host | `provider.sort: throughput`, `:nitro` | `sort=throughput` |

`effort` is the wisher's word for the generic contract (#595). `thought` is the wish's word for
the spent tokens. `sort` is openrouter's own word, kept so a reader of either doc meets one term.

## .composition with the in-flight trees

| tree | its lever | meets this tree at | rule |
|---|---|---|---|
| latency filter (`beav/feat-latency-filter`) | a slug filter word: excludes slow hosts | which hosts qualify | **filter first, sort second.** no conflict: the filter narrows, the sort orders what remains |
| prompt-cache affinity (`beav/feat-prompt-cache-affinity`) | a pin to the host that cached the prefix | which host goes first | **affinity wins.** a cache read beats any cold host on cost and prefill. sort orders the fallbacks behind the pin. the report names both (case=5, F08) |

all three levers at once resolve in one order: **filter → pin → sort**. the filter is a promise,
so it binds even the pinned host. a pin whose host fails the bound yields, and the report says so
(case=5 [t4]). `effort` never meets them: it changes the body, never the host order.

neither tree has code yet (both at `c7dbbd8`). whichever merges second wires the precedence, and
case=5 [t1]–[t4] are its clamps.

## .evaluation

**goals met.**

| wish line | how |
|---|---|
| cap per ask, tokens or effort | `effort` on the ask, forwarded as `reasoning` |
| sort per ask | a `sort=` slug word, forwarded as `provider.sort` or as the walk order. per ask by choice of atom: the caller picks the slug per ask |
| both optional; unset = 0.1.3 | case=3. no key is sent when unset |
| an all-thought reply is named | case=2. a distinct error, never an empty verdict |
| each reply reports thought tokens | `metrics.size.tokens.thought` |
| tests prove the body, and absence | case=1 [t0], case=3 [t0] |
| composes with the two trees; says which wins | the composition table above + case=5 |
| (found on this route) a cut or stalled host never kills nor hangs the ask | the walk steps past it; case=9 |

**pros.**
- thought rides the generic contract the wisher ruled for (anthropic tree F12, 2026-08-31), so
  every brain meets one `effort` shape, and bhrain writes it once for every supplier
- sort joins the grammar that already carries every other supply choice; no second channel
- the cap is enforced, not hoped for: `reasoning` joins the params a host must list, so a host
  that would ignore it is never admitted (case=6)
- under floor, sort keeps every promise. it changes only the order of the walk

**cons.**
- a local patch of a peer dependency, until #595 releases. bhrain needs the same patch to
  typecheck its call
- a sort per slug means one listed slug per sort a consumer wants to choose. this tree lists one:
  the reviewer floor with `sort=throughput` (F02)
- `latency` sort under `floor` waits on the latency tree to parse `latency_last_30m` (F04)

**edge cases, and the pit of success.**
- level and budget together → forbidden by `PickOne`, refused at runtime (case=7)
- budget ≤ 0, fractional, or a level outside `spec.supports.effort.levels` → refused before
  spend, with the valid levels listed (case=7)
- an effort no host can honor → the funnel error names `reasoning` (case=6)
- a reply cut mid-answer, not all thought → the extant cut-off error, with thought tokens added
- a host that reports no `reasoning_tokens` → `tokens.thought = null`, never a fake 0
- no default effort. per the wish bound, any default a tier carries must be generous, and "none"
  is the most generous (F05)

## .groundwork

### external research

- openrouter reasoning — https://openrouter.ai/docs/use-cases/reasoning-tokens (read 2026-10-07):
  `reasoning: { effort | max_tokens, exclude, enabled }`. **one of** effort or max_tokens, never
  both. effort ∈ minimal · low · medium · high · xhigh · max · none (this package lists the first
  four in `spec.supports.effort.levels`; F07). reasoning tokens count within output, reported at
  `usage.completion_tokens_details.reasoning_tokens`. budget exhausted ⇒ `finish_reason: length`,
  content empty, thought still billed
- openrouter provider routing — https://openrouter.ai/docs/features/provider-routing (read
  2026-10-07): `provider.sort` ∈ price · throughput · latency. sort disables the balancer and
  orders within `only`. with `allow_fallbacks: false`, only the top host serves
- openrouter endpoints api — `GET /api/v1/models/deepseek/deepseek-v4.1-flash/endpoints` (read
  2026-10-07): all 28 hosts list `reasoning`, `include_reasoning`, and `reasoning_effort`. so the
  param requirement drops no flash host today; case=6 stays a rare alterpath. each endpoint also
  reports `max_completion_tokens` and `latency_last_30m` (q5, q6)
- ⚠️ a listed param is not an honored one. q1 owes a live completion probe before any criterion
  leans on it

### internal research

- `BrainAtom.d.ts:64-76`, `ContextBrain.d.ts:41-58` (rhachet 1.48.1): the atom ask and the choice
  ask hold `on, plugs, role, prompt, schema`. the patch adds `effort` to both
- `asBrainAtomWithContextBound.js:19-20`: the input passes to `brain.ask` untouched, so `effort`
  reaches the atom at runtime with no rhachet code change
- `genBrainAtom.ts:225-241`: the request body. `reasoning` joins here
- `asAskNeeds` → `paramsRequired` (`genBrainAtom.ts:208`): the extant path by which a request
  field excludes hosts that do not list it. `effort` reuses it
- `asSupplyFilters.ts`: the filter grammar. `sort` joins `FILTER_KEYS` and `VALID_WORDS`. a slug
  with its own segment replaces the default whole (line 48), so a sort slug writes the full
  segment; no merge rule is added
- `AtomSlug.filtered.ts`: `SLUGS_FILTERED_LISTED` holds the reviewer floor. its `sort=throughput`
  twin joins it, and `SLUGS_PROMISED_FOREVER`
- `asProviderPreference.ts`: the `provider` object. `sort` joins as a conditional spread, like
  `zdr` and `max_price`
- `getAllQualifiedEndpoints.ts:127-131`: the rank comparator — input cost, then throughput. the
  floor walk consumes that order. sort swaps the primary key. there is no latency field
- `getAllQualifiedEndpoints.ts:58-66,169`: a required param becomes the funnel step
  `supports(…)`; case=6 reuses it as is
- `getOneFloorCompletion.ts:113-135`: `isReplyFailed` steps past a failed reply; `asStepOutcome`
  classifies a thrown error as step-or-throw. a body-cut and a stall join it
- `genBrainAtom.ts:146`: the openai client is built with no `timeout`
- `getOneReplyDefectError.ts:53-62`: today `finish_reason=length` maps to "cut off… ask for a
  shorter reply". the all-thought case splits off ahead of it
- `asBrainSizeTokens.ts`: reads `prompt_tokens`, `completion_tokens`, `cached_tokens`. the
  `reasoning_tokens` read joins here
- error vocab: `ConstraintError` for caller-fixable refusals (`asSupplyFilters.ts`),
  `MalfunctionError` for reply defects (`getOneReplyDefectError.ts`)

## .what is awkward

- **`floor` + `sort=throughput`.** "floor" says cheapest, yet the walk runs fastest-first. the
  walk keeps the floor's mechanics (one host per hop, no balancer), not its price claim. the
  report names the sort so the charge is not read as a floor price (F03)
- **a patch of a peer.** it proves the shape here but does not reach consumers. it is honest only
  while it matches #595 exactly (F10)
- **the thought-exhausted error class.** it is caller-fixable (set or lower a budget), which
  reads `ConstraintError`. it is also a probabilistic reply defect, beside its `MalfunctionError`
  peers. the sketch keeps `MalfunctionError` for family consistency (F06)
