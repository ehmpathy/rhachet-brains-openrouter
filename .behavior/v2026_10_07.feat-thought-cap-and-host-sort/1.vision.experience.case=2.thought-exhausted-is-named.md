# case=2 — thought eats the whole reply room, and the error says so

sharp × critipath. cells: `d1=budget=N × d4=thought-exhausted` [t1],
`d1=unset × d4=thought-exhausted` [t2] — the measured bhrain case.

## .narrative

today: a review ask thinks until the host's output limit, writes no verdict, and returns
`finish_reason: length` with empty content. bhrain reads "cut off at the output limit… ask for
a shorter reply" — the wrong fix: the reply was never started. it paid ~2× the input cost for it.

after: the same reply raises an error that names the cause — the whole reply was thought — and
the lever: a thought budget, or a lower one. its evidence carries the thought tokens and the
budget, so bhrain can size the next budget from the number in hand. it never reads as a sound,
empty verdict.

## .sketch — the error

```
💥 MalfunctionError: openrouter's host spent the whole reply on thought, and wrote no answer
   (7998 of 8000 output tokens were thought; finish_reason=length; 0 chars of answer).

fix: budget thought below the output room, so the answer has space —
  atom.ask({ ...input, effort: { budget: { tokens: 6000 } } })
audit: https://openrouter.ai/activity — generation gen-…, provider DeepInfra
```

with a budget set, the fix line reads `lower effort.budget.tokens (now 7900)`.

## .fails safe

- **fast** — one reply, one error. `finish_reason=length` is not a host failure
  (`isReplyFailed.ts:28` reads only `error` and null), so the floor walk does not step to a second
  host and pay for the same thought twice
- **loud** — a thrown error, never an output that parses to an empty verdict
- **teaches** — the fix names the lever and the number to move

## .timeline

```
given('[case2] a host whose reply is all thought: finish_reason=length, content empty, reasoning_tokens ≈ completion_tokens')
  when('[t1] the ask set effort.budget.tokens = 7900')
    then('the ask rejects with the thought-exhausted error, never a parsed output')
    then('the floor walk tries no second host — another host would spend the same thought again')
    then('the error evidence holds thoughtTokens, outputTokens, budget')
    then('the fix line names a lower budget')
  when('[t2] the ask set no effort')
    then('the ask rejects with the same error, never the "ask for a shorter reply" text')
    then('the fix line names a thought budget to set')
```

the neighbor cell, a reply cut mid-answer (`answer-cut`), keeps the extant cut-off error and is
itemized in the inventory, not demoed here.
