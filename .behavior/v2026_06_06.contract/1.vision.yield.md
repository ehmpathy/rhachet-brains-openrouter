## user experience

### usecases

| usecase | goal | recommended slug |
|---------|------|------------------|
| **code review** | high-quality code analysis | `fireworks/kimi/k2.5` (76.8% swe-bench) |
| **code generation** | fast iteration on code | `fireworks/qwen3/coder-next` (74.2% swe-bench) |
| **bulk processing** | cheap high-volume inference | `fireworks/deepseek/v4-flash` ($0.14/1M in) |
| **complex reasoning** | frontier-level tasks | `fireworks/deepseek/v4-pro` (1M context) |
| **general assistant** | balanced cost/quality | `fireworks/qwen3/235b` |

### contract inputs & outputs

```ts
// input: select model by slug
const brainAtom = genBrainAtom({ slug: 'fireworks/deepseek/v4-flash' });

// input: prompt with optional briefs, schema, tools
const result = await brainAtom.ask({
  role: { briefs: [codeReviewBrief] },
  prompt: 'review this PR diff',
  schema: { output: z.object({ issues: z.array(z.string()), approved: z.boolean() }) },
  plugs: { tools: [lintTool, testRunnerTool] },
});

// output: typed response with metrics
console.log(result.output);           // { issues: [...], approved: true }
console.log(result.metrics.cost.cash.total); // '$0.002'
console.log(result.calls?.tools);     // tool invocations if any
```

## evaluation

### how well does it solve the goals?

| goal | solution | confidence |
|------|----------|------------|
| support cheapfast models | add v4-flash, minimax, etc. | high |
| support frontier models | add v4-pro, k2.6, glm-5.1 | high |
| prove integration tests | extant pattern scales | high |
| focus on tooluse codefocus | extant tool tests, add to new models | high |
| update readme | add tier table, pricing, benchmarks | high |

### pros

- **unified interface**: same `genBrainAtom` / `ask` pattern for all models
- **type safety**: slugs are typed union, autocomplete guides selection
- **cost transparency**: specs include exact pricing from fireworks
- **proven tests**: integration tests prove each model works with briefs + tools
- **openai-compatible**: uses openai sdk under the hood

### cons

- **fireworks limitations**: no structured output + tools simultaneously (vllm constraint)
- **model availability**: some models (kimi/k2) have 503 issues
- **pricing changes**: fireworks updates rates, we must track
- **no caching discount**: fireworks cache rates not always clear

### pit of success

| edgecase | how contracts keep users safe |
|----------|------------------------------|
| invalid slug | TypeScript rejects at compile time |
| tools + structured output | `BadRequestError` with clear message |
| absent api key | fail-fast with helpful error |
| model 503 | `then.repeatably` pattern in tests demonstrates retry |

## open questions & assumptions

### assumptions

1. **fireworks pricing is stable** — we assume the rates we document won't change weekly
2. **tool use works on listed models** — we assume models with `skills: { tooluse: true }` actually support it
3. **swe-bench scores are accurate** — we trust fireworks' published benchmarks
4. **new models are production-ready** — we assume v4-pro, k2.6, etc. are stable on fireworks

### questions for wisher

1. **model selection criteria**: should we include ALL models fireworks offers, or curate to "best in tier"?
2. **deprecated models**: should we remove kimi/k2 given 503 issues, or keep for users who want to try?
3. **benchmark requirements**: do we need swe-bench for all models, or is it optional?
4. **pricing format**: should readme show both fireworks and author-direct pricing (like current deepseek comparison)?

## what is awkward?

### fireworks limitations

- **no structured output + tools**: vllm constraint means we must output `z.string()` when tools are plugged on initial call. users must parse the string themselves if they need structure.
  - **tradeoff**: this is fireworks' limitation, not ours. we document it clearly.

### model availability

- **scale-from-zero 503s**: fireworks deployments scaled to zero return 503 with `DEPLOYMENT_SCALING_UP` until warmed up. tests must implement retry with exponential backoff.
  - **source**: [fireworks docs](https://docs.fireworks.ai/updates/changelog) — retry guidance for scale-up delays
  - **tradeoff**: integration tests use `then.repeatably` pattern to handle cold starts.

### pricing staleness

- **rates change**: fireworks updates pricing, our config becomes stale.
  - **tradeoff**: we document sources and last-verified date. users can verify at fireworks.ai/pricing.

### slug explosion

- **many models**: adding all models means ~20+ slugs, longer type union.
  - **tradeoff**: curation. we include "best in tier" not "all available".
