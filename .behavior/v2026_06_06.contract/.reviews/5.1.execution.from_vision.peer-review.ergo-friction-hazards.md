# blocker.2: unclear errors from underlying openai api calls

**rule**: .agent/repo=bhuild/role=behaver/briefs/practices/behavior.execution/architect/rule.forbid.friction-hazards.md

**locations**:
- src/domain.operations/atom/genBrainAtom.ts:170

The ask implementation performs the openai.chat.completions.create call with no try/catch, no error wrapping, and no transformation into a BadRequestError with actionable hint. API failures (invalid key, rate limits, network, model errors, 4xx/5xx) surface raw library errors to the caller. This violates error clarity requirements: errors must tell the user what went wrong AND how to fix it. No acceptance tests or snapshots cover these error paths (integration tests only exercise happy paths and specific tool-signal cases).

**snippet**:
```ts
      const response = await openai.chat.completions.create({
        model: config.model,
        messages,
        ...(hasTools ? { tools, tool_choice: 'auto' as const } : {}),
        ...(wantStructuredOutput
          ? {
              response_format: {
                type: 'json_schema',
                json_schema: {
                  name: 'response',
                  strict: true,
                  schema: jsonSchema,
                },
              },
            }
          : {}),
      });
```
