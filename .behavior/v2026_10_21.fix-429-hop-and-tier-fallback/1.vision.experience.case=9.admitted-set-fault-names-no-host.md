feel: sharp · care: critipath · seats: participant, then reader

## narrative
a ci suite asks on a filtered slug, no floor; A, B, C qualify. openrouter answers `429 Rate limit
exceeded`, with no `provider_name` and no `Provider returned error` marker — its own account
limit, not one host's. the suite cannot be helped by a hop or a walk: no other host can lift the
account limit, and every extra send would meet the same 429 and prolong the limit. so the ask
fails at once, with the untouched `RateLimitError` — one send (plus the openai client's own two
retries), no hang. the on-call reads the real cause: openrouter's limit, not a broken host.

the same holds for a 404 with no mark: openrouter withdrew the model, and no host can serve it.

a fault that DOES carry the host marker yet names no host is a different cell: it is a host's
fault, so the set is walked — c15.
