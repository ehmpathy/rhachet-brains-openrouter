# 1.vision — a host fault walks to the next host

## .the outcome world

a host fault is the host's problem, never the caller's. openrouter picks a host; that host
throttles (429), is unreachable (404), or rejects the request with its own error (400 that names
it). the ask steps to the next qualified host, in both supply modes:

- **floor walk** (`floor` in the slug) — one host admitted per hop, cheapest first
- **admitted set** (no `floor`) — every qualified host admitted at once; openrouter balances

only a fault the caller caused — a malformed request, a 400 that names no host — fails loud,
untouched.

### before / after

| reply | floor walk, before | floor walk, after | admitted set, before | admitted set, after |
|---|---|---|---|---|
| 429 | step | step | 🔴 ask fails | step: drop that host from `only`, re-send |
| 404 | step, drop cache | step, drop cache | 🔴 ask fails | step, drop cache |
| 400 that names a host | 🔴 ask fails | step | 🔴 ask fails | step |
| 400 that names no host | fails loud | fails loud | fails loud | fails loud |
| 500, 401, else | fails loud | fails loud | fails loud | fails loud |

Request could not be processed` from host OpenInference on `openrouter/deepseek/flash`. after:

## .the contract

### one decision, one transformer — `asHostFault`

```ts
asHostFault({ error }): { outcome: 'throttled' | 'refused' | 'failed'; providerName: string | null; isHostMarked: boolean } | null
```

| error | verdict |
|---|---|
| not an `OpenAI.APIError` | `null` — rethrow |
| 429 | `throttled` |
| 404 | `refused` |
| 400 with `error.metadata.provider_name`, or with message `Provider returned error` | `failed` |
| 400 with neither | `null` — the caller's fault, rethrow |
| else | `null` — rethrow |

`providerName` reads `error.error.metadata.provider_name`, openrouter's mark of a provider error;
`null` when absent. a host 400 counts on either signal, since the 2026-10-21 logs named a host on
only one crew. both paths call it; it replaces the floor walk's private `asStepOutcome`.

- floor walk steps on any host fault — it admitted one host, so it knows which
- admitted set hops when `providerName` names an admitted host. a host-marked fault
  (`isHostMarked`: a name, or the `Provider returned error` marker) that names no admitted host
  walks the set one host per send. a fault with no host mark is openrouter's own answer (its
  account-limit 429, a withdrawn model's 404); it rethrows untouched (c9)

⇒ `feat-thought-cap-and-host-sort` owns the transport half (cut body, stall) and adds its rows to
this same transformer. see fulcrum F1.

### the outcome vocabulary — no new word

`FloorAttempt.outcome` stays `served | throttled | refused | failed | prose`. a host 400 is
`failed`: the host failed this ask. `failed` already means "the host failed mid-reply"; the note
widens to "the host failed this ask: mid-reply, or with its own error". no cache drop, same as
today's `failed`.

### the admitted-set hop

```
send(only = qualified)
  ├─ served                      → return; admitted = the final `only`, which the served check
  │                                 reads; attempts = the hops taken, then the `served` row
  ├─ host fault, names a host    → drop every endpoint of that provider from `only`
  │  in the set                     attempt per dropped tag; keep the latest retry-after
  │                                 404 also drops the model's cached endpoint list
  │                                 re-send with what is left
  ├─ host fault, marked, names   → walk the set one host per send, as the floor walk does
  │  no host in the set             (cannot tell which host to drop; each send names it by `only`)
  ├─ no host mark                → rethrow untouched: openrouter's own answer (c9)
  └─ not a host fault            → rethrow untouched
admitted set empty               → refuse loud: each hop + its outcome + retry-after
```

the empty-set refusal reuses the floor walk's exhausted error, `getOneFloorExhaustedError` —
same attempt trail, same `retry after Ns` fix line. its "failed mid-reply" phrase widens to
"failed (mid-reply or with its own error)". its floor-only name is left; see the dream.

## .mental model

how a caller says it: *"if a host chokes, the ask moves to the next one."*

analogy: a taxi rank. the dispatcher (openrouter) waves you to cab A. A's driver says "off duty"
(429) or "not that route" (400 that names A). you walk to the next cab in the rank, not home. only
when you hand the driver a nonsense address (400 that names no host) is it your problem.

| caller's word | our word |
|---|---|
| host choked / host down | host fault |
| try another | hop / step |
| ran out of hosts | supply exhausted |

## .evaluation

**goals.** both #21 and the host-400 defect close at one seam (`asHostFault`), one clamp each.
#22 and #23 stay out; they ride a follow-up tree.

**pros**
- one decision for "is this a host failure", shared by both paths and by the thought-cap tree
- no new outcome word; the attempt trail and the exhausted error keep their shape
- the admitted set keeps its cache stickiness (openrouter still balances within `only`) and gains
  the floor walk's resilience

**cons**
- the admitted-set hop relies on `provider_name` in the error body. if openrouter omits it on a
  marked fault, the set is walked one host per send (c15): resilient, at the cost of one extra
  send per walked host. if the fault carries no host mark, the ask fails as today (c9)
- a provider with several tags (`deepinfra`, `deepinfra/fp8`) leaves `only` whole. a throttle is
  per account at that provider, so this is the right grain

**pit of success**
- the hop strictly shrinks `only`; a host fault that names no admitted host walks the set at most
  one send per endpoint (c10, c15); a fault with no host mark rethrows in one send (c9). no loop
- a 400 with no host name never steps: a malformed request fails at the first send, not after N
  wasted re-sends

## .what is awkward

- the hop is not instant on a 429. the client (`genBrainAtom.ts:146`) keeps the openai sdk's
  default `maxRetries: 2`, so the sdk re-sends a 429 to the same `only` twice, with backoff,
  before the hop sees it. 400 and 404 are not sdk-retried. a `maxRetries` change would touch
  every ask — out of scope.
- the fix that seems simpler — `allow_fallbacks: true` with `only` — is refused: the docs do not
  say a fallback stays inside `only`, and `asProviderPreference` pins it off to guard the privacy
  and price promises. see fulcrum F5.
- `FloorAttempt` and `getOneFloorExhaustedError` now serve both paths, yet are named for one. a rename ripples into
  `SupplyReport` and every importer — out of scope today; caught as a dream.
- `supply.attempts` ends on the `served` row in both modes; the composer appends it once, after
  the served check. on the admitted set this changes a first-try serve from `[]` to
  `[{ tag, served }]` — a caller that checks `attempts.length === 0` sees the change.
- `failed` now spans "200 that failed mid-reply" and "400 that names the host". one sense — *the
  host failed this ask* — but the reader learns the wider sense from the note.
