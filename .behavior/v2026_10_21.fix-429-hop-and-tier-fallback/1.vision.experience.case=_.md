## the product, reduced

raw product = path (2) × status (5) × flag (2) × name (3) × left (2) = 120 tuples. split by the
decision each reaches. within a group, each tuple either **collapses** into a reduced cell or is
**impossible**:

- **collapsed** — the axis has a value, but the group's decision does not read it
- **impossible** — the axis has no value by nature: a served reply has no error body, so no
  `flag` or `name`; a cell with no hop has no post-hop set, so no `left`

| served | 2 × 1 × 2 × 3 × 2 = 24 | — | flag, name (no error body); left (no hop) | 2 (path) |
| unrecognized | 24 | flag, name — the rethrow does not read them | left (no hop) | 2 (path) |

| floor host faults: 429 (6 flag×name) · 404 (6) · 400 host-marked (5) | 1 × 17 × 2 = 34 | flag, name — inert on floor (I3) | — | 3 statuses × left 2 = 6 |
| admitted host faults: same 17 | 34 | flag, when name ≠ absent — a name already marks the host | left, when name ≠ admitted (no hop; the set is walked or the fault rethrows, I2) | 429, 404: admitted × left 2 + absent × flag 2 + stranger = 5 each · 400 host-marked: admitted × left 2 + absent (flagged alone) + stranger = 4 · = 14 |

tuple lands in one group, and there either collapses into a reduced cell or is impossible for the
reason its row names. none is unaccounted for.

## variants — rows that ride on a cell, not new cells

a variant changes what a cell renders, never its verdict, so it adds no cell to the census.

| case | rides on | variant | feel | care | verdict |
|---|---|---|---|---|---|
| c16 | c1, c2, c8 (admitted, `name = admitted`) | the named provider owns several admitted endpoints: the hop drops all of them in one step; `supply.attempts` holds one row per endpoint dropped | happy | alterpath | itemized — found at verification; clamped by admitted `[case8]` (snapped), `asEndpointsSplitByProvider.test.ts`, `asSupplyAttemptsOfFault.test.ts` |

care test for c16: *if this broke, would a core usecase fail?* no. a hop that dropped one
endpoint of the provider would re-send to the other endpoint of that same provider, which may
fault again and hop once more: one more send, the ask still served. the trail would under-report,
which the reader seat feels, but no ask fails. so it is an alterpath, itemized, with no `case=N`
demo owed.
