# case=7 — key credit limit exhausted

**feel** sharp · **care** critipath (every key with a limit hits it eventually — by design)

## narrative

dana's reviewer fleet shares one key. mid-run, twelve parallel asks hit its $5 weekly limit.
dana's log shows twelve copies of one plain message, not twelve opaque 402s: the key's limit
is spent; raise it at `/settings/keys` or wait for the weekly reset. dana raises the limit and
reruns the fleet. had the account balance run dry instead, dana would read the same message
shape, sent to `/settings/credits`, top up, and rerun.

## [tn] sketch

```
given('[case7] a key whose limit is spent')
  when('[t0] dana's fleet asks')
    then('ConstraintError names openrouter_key_limit and /settings/keys')
  when('[t1] dana's fleet asks on an account whose balance is spent instead')
    then('ConstraintError names openrouter_credits and /settings/credits')
  when('[t2] dana's other asks are still in flight')
    then('each fails with the same named error; none retries on its own')
  when('[t3] dana's ask fails for any other reason')
    then('it rethrows untouched (no failhide)')
  when('[t4] dana's floor ask meets the 402 on its first endpoint')
    then('the walk stops at once; no hop to the next endpoint')
```

a 402 is key-wide or account-wide: every endpoint would answer the same. so the floor walk
(case=21) stops at the first 402 — a hop would spend a round trip per endpoint to learn naught.
